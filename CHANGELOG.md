# Changelog

## [Unreleased]

- `quint_driver targets [APP] [--top N]` ranks the files of an app's `app/` and `lib/` where a hunt pays. It marks each line that matches a kind of place where the bugs a hunt finds sat (a transaction, a rescue, a save without `!`, a method that answers `false`, a call that drops what such a method answers, a write that skips callbacks, a counter write, a retry, an outside call) and ranks the files by how many kinds meet in each. `QuintDriver::Targets.scan(root)` returns the hits. It reads each file with Prism, which ships with Ruby, so comments, strings, heredocs, regexps and `=begin` blocks are not matched, and a call drops what a method answers only when the def that holds the save is that method; a method named as many others are, such as `call` or `perform`, counts only where its class is named. `check-then-write` marks a write, or a call of an app method that writes, after an `if` or `unless` that reads stored state, in a method that takes no lock, and an error class of the app's own counts as `outside`. A save the line itself reads, as in `save or raise`, is no `unchecked-save`. When nothing matches, the report names what to read instead. `--top` below 1 and an APP that is no directory exit 1 with the reason.
- `QuintDriver::Hold#pause` raises `ArgumentError` when it runs in a Fiber of its own inside a held call, such as the block of an `Enumerator` read with `next`, where it cannot stop the call; it did nothing, and the call ran through unheld. A held block that calls `Fiber.yield` itself raises `ArgumentError` too.
- `quint_driver outline` says above `state` that a variable the system does not keep goes in `ignore:`.
- The model reads a `val` inside an action only when the action needs it, as Quint does, so a `val c = m.get(r)` above the guard that makes `r` a key no longer raises `Unsupported` on a move Hegel tries and the spec does not allow. A `def` with parameters inside an action or a def is a local operator the model calls; it raised `` quint: no evaluation for operator <name> ``.
- An `Unsupported` the model raises starts its backtrace at the caller's line, with no frame of quint_driver, as a `Mismatch` does.
- `Spec.new(path)` reads the module named after the file when `main:` is left out, as `Quint.simulate` does.
- `Spec#expectations` lists the names `invariants:` and `violate:` take, every boolean `val` or `def` without parameters, in the order the module declares them.
- `QuintDriver::Hold` stops a call part way and lets it go on in a later step, so a spec can split a request into the step that reads and the step that writes and put another request between them. `start(name) { ... }` runs the block until the code calls `pause(value)` and returns that value, `finish(name)` runs it to its end and returns the block's value, and `pause` outside a held call does nothing. A held call runs in a Fiber on the same thread and shares its database connection. `examples/shelf` loses an update this way, and the skill's "A request another one comes between" shows it.
- The gem installs a `quint_driver` command. `quint_driver outline SPEC.qnt [--main MODULE] [--step ACTION]` prints a driver to start from: a `when` for each action the step action can take, with the picks it receives and the Ruby shape of each, a key for each variable `state` must report, with the shape of its value, and the spec's expectations. When the step action has a shape the driver protocol cannot run, it prints the `Unsupported` message and exits 1. `Spec#outline(step = "step")` returns the same text.
- `QuintDriver::Quint::Simulation` gains `actions`, how many steps each action took across every trace quint ran, and `never`, the actions of the step action that no trace took, so a hunt that found nothing can tell whether it tried every action. `never` is `nil` when the step action has a shape the driver protocol cannot run.
- `QuintDriver.replay_steps(spec, driver, steps, step: "step", observe: [], ignore: [], invariants: [])` runs a list of steps on the driver and on the spec's model from `init` and checks each one as `Trace.replay` does, raising `Mismatch` or `Violated` with the same message. `steps` is the text under `steps:` of a failure, pasted as it is, or a list of `[action, picks]`, so a failure from a trace or from Hegel becomes one example that needs no quint run and no Hegel. A step the spec does not allow raises a `Mismatch` that names it.
- `QuintDriver::Violated` is a new error, and no `Mismatch`: the system agreed with the spec at every step, and an expectation does not hold. Its message names the expectation and the step, lists the steps from `init`, gives the spec's variables in the state where it broke, and names the trace as a `Mismatch` does.
- `Trace.replay` takes `invariants:` with `spec:`. The model evaluates each named predicate in each state of the trace after the step's agreement check, and one that is false raises `QuintDriver::Violated`. A name that is no boolean `val` or `def` without parameters, or `invariants:` without `spec:`, raises `ArgumentError` before the first step.
- `QuintDriver.machine` raises `QuintDriver::Violated` where an expectation that `invariants:` names does not hold, in place of a `Mismatch` that read ``quint: the model broke `name` ``. The message names every expectation that broke in that state, the move by the number Hegel's report gives it, the shrunk steps from `init`, and the state. A name that is no boolean `val` or `def` without parameters raises `ArgumentError` from `QuintDriver.machine`, before Hegel runs.
- `Quint.simulate` takes `violate:`, the name of an expectation. quint checks it as its invariant, each trace ends at the first state where it is false, and only the traces that break it are yielded. When every trace keeps it, nothing is yielded and nothing raises. `violate:` takes a predicate as `reach:` does and needs `backend: "rust"`, and `reach:` with it raises `ArgumentError` before quint runs.
- `Quint.simulate` returns a `QuintDriver::Quint::Simulation`, whose `traces` is how many traces quint ran and whose `violated` is how many of them broke the `violate:` expectation, or `nil` without `violate:`. It returned the paths of the trace files, which were gone by then.
- `Quint.simulate` refuses `reach:` with `backend: "typescript"`, with an `ArgumentError` before quint runs. quint 0.33.0's typescript backend runs a trace on past the state where the definition first holds and marks every trace after the first such state as one that reached it, so it yielded traces that never got there.
- The skill gains "Choose a target" and "Hunt for bugs", and the README "Hunt for bugs": write what the code does as actions and what the operator expects as boolean `val`s, aim `violate:` at each expectation, and read `Violated` as a bug suspect. `test/fixture/depot` in the repository, a Rails app with four planted bugs, is the worked example.

## [0.1.0] - 2026-11-13

First release. quint_driver holds Ruby code to a [Quint](https://github.com/quint-co/quint) spec: a driver runs each action of the spec on your code and reads your code back as the spec's variables, and quint_driver compares the two after every step.

- `QuintDriver::Quint.simulate` runs `quint run --mbt` and yields each trace, and `QuintDriver::Trace.replay` runs a trace on a driver step by step. `reach:` ends each trace at the first state where a definition holds. `QuintDriver::Quint.test` replays the trace of a named `run`.
- `QuintDriver.machine` builds a `Hegel::StateMachine` from the spec, so [hegeltest](https://github.com/meganemura/hegel-ruby) picks each step from the actions the spec allows now and shrinks a failure to a short sequence of commands. `invariants:` names the spec's `val`s that must hold after every move. It loads with `require "quint_driver/hegel"`.
- A driver reports every variable of the spec. A variable its `state` leaves out fails the step and is named, so a forgotten one cannot pass. `ignore:` on `Trace.replay` and `QuintDriver.machine` names the variables the driver only reads, such as what a remote service answers.
- `QuintDriver::Mismatch` names each variable that differs and the steps from `init`, so the failure can be run again by hand. An error a step raises, in the driver or in the system, comes out as `QuintDriver::StepRaised`, and a failed `quint` command as `QuintDriver::QuintFailed`.
- The spec is read from Quint's JSON IR and evaluated in the Ruby process (`Spec#model`), so a Hegel step starts no other process. The model can be held to Quint's own traces with `Trace.replay`. An operator it does not know raises `QuintDriver::Unsupported`. A pick can be any value the spec draws, `false` and `None` included, and `Bool` is the set of both booleans. A pick from `Int` or `Nat`, which no move can list, raises `QuintDriver::Unsupported`.
- `Quint.simulate` runs Quint's Rust evaluator directly when quint has downloaded it, without node.
- An agent skill in `skills/quint_driver/`. It shows, among others, a driver for code that calls remote services: the spec models what the service answers, and the driver stubs the service from it and counts the calls. It also shows how a spec picks one of the orders the code leaves to the database, such as the three rows of a `has_many` read with no ORDER BY, and how the driver enacts that pick; `test/skill_test.rb` runs that example in a Rails app on SQLite or PostgreSQL. The gem ships it with the `examples/loans` spec and `README.ja.md`, so `bundle info --path quint_driver` finds them without GitHub access.
- Ruby 3.3 or newer, with no runtime dependency. The Hegel adapter needs hegeltest 0.5.1 and Ruby 3.4 or newer, in your own Gemfile.
